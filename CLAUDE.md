# Impossible Hill Climb — BACKEND (game server)

Frontend (3D client) lives at `../Bowling-roll` (`src/net.js`). Colyseus + Mongo.

- `npm start` (tsx watch, port 2567), `npm run build` (tsc -> `build/`), `npm test` (mocha + `@colyseus/testing`, Mongo faked via `__setPlayersForTest`; tests share one booted server, `test/server.ts`). Node >= 22.
- One room, `world` (`src/rooms/WorldRoom.ts`, client calls `joinOrCreate("world", { userId, username, pfp, loadout, avatar })`). Client-authoritative: the server only bounds/sanitises saves (`src/sanitize.ts`). `src/db.ts` degrades to "no persistence" when `MONGODB_URI` is unset/unreachable; guests (`guest-` ids) are never saved. `/health` for Legion; `/monitor` and the playground are dev-only.
- Saves: signed-in players' Mongo doc is their save. Nothing is stored in the browser: guests and serverless play last the page only. Rewards (chest, daily, spin) are client-side and saved like everything else (`lastChest`, `daily`, `spins` + `spinTimer`); there is no server-authoritative system.
- Messages client -> server: `saveProgress` (the whole snapshot, debounced client-side), `identify` (`{ userId, username, pfp }` after a sign-in/out mid-session), `pose`, `loadout`, `setAvatar`. Server -> client (private): `progress` (the saved doc, sanitized), `noProgress` (new account, guest, or no database: the client keeps its state and saves it), `serverError` (the save could not be read: saving stays off so it is never overwritten), `leaderboard`. Saves are ignored until the session's load has answered (`loaded`). A second live session on the same account is evicted.
- Saved progress shape (`PlayerDoc`; keys are the client's `state` keys, `SAVED_KEYS` in `src/game/state.js`): `speed`, `level`, `xp`, `wins`, `gems`, `rebirths`, `bike` + `ownedBikes[]` (equipped must be owned), `pets[] { uid, id }` + `equippedPets[]` (owned uids) + `nextPetUid`, `trail` ("none" = none) + `ownedTrails[]` (bought or won), `petSlots` / `petStorage` (pet equip and storage caps), `boosts { speed, wins }` (unix s), `customSpeed`, `lastChest`, `daily { streak, last }`, `spins` (banked wheel spins), `spinTimer` (s of play to the next free spin), `played` (s), `boulderStop`, `introSeen` (watched or skipped the new-player intro; boolean), `lastSeen`.
- Leaderboards (`src/leaderboard.ts`): top `LEADERBOARD_SIZE` saved players by each of `LEADERBOARD_STATS` (`wins`, `speed`, `played`, `rebirths`), cached process-wide for `LEADERBOARD_EVERY_MS`; own rank = countDocuments(stat > yours) + 1. `leaderboard` { boards: { stat: [{ name, value }] }, ranks } is sent after each load and every `LEADERBOARD_EVERY_MS`. The client's boards in `lobby/zones.js` show them (fake rows while offline).
- Presence (`src/presence.ts`): roster fields `x/y/z` (feet, world metres), `yaw`, `speed`, `bike`, `trail`, `pets` ("pup,fox", max `PRESENCE_PETS_MAX`), `avatar` (Bloxity look JSON). The client sends them; it does not draw other players yet.
- `src/constants.ts` bounds must cover the client's `src/config.js` (catalog ids match `ID_PATTERN`). A contract change goes in both projects.
- CI/CD: `.github/workflows/deploy.yml` tests on PRs and pushes to `main`/`dev`; pushes also build+push a GHCR image and deploy to Bloxity Legion (`main` = prod, `dev` = dev), sending `roomSize` = `ROOM_MAX_CLIENTS` from `src/constants.ts`. Needs repo var/secret `LEGION_GAME_ID` (= `impossible-hill-climb`) and secret `LEGION_DEPLOY_TOKEN`.
- **Identity is the Bloxity game token**, never a client-sent id: the client joins with `{ token, username, pfp, loadout, avatar }` (and sends `identify { token }` on sign-in/out). `src/auth.ts` verifies it (`POST {BLOXITY_API_URL}/v1/auth/game-token/verify`, Bearer token, `{ gameSlug }`) and uses only the returned `user._id`; a failed/missing token = guest. Only in local dev (NODE_ENV != production and no BLOXITY_API_URL) a `dev-xxxx` `userId` is accepted. Roster `uid` = the verified account id (the client matches chat bubbles to riders by it).
- Bloxity hosting: `src/bloxityBoards.ts` batches the saved wins/speed/rebirths/played to the hosted leaderboards (`POST {BLOXITY_API_URL}/v1/leaderboards/hosted/{BLOXITY_GAME_ID}/report`, Bearer `BLOXITY_REPORT_TOKEN`, every 15 s; the ids must match the client's `LEADERBOARDS`). `src/legion-room-reporter.ts` (`installRoomReporter()` after `listen()`) posts this pod's rooms to the matchmaker every 2 s so friends' Join / invites work; it no-ops unless `BLOXITY_REPORT_TOKEN`, `MATCHMAKER_REPORT_URL` and `BLOXITY_GAME_ID` are set (see `.env.example`). Tests map tokens `tok-<id>` to accounts with `__setVerifierForTest` (`test/server.ts`).
- The client now draws every other rider from the presence fields (`src/game/remotePlayers.js`).
